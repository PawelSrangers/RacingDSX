# ADR-0009: Определять блокировку колёс по скорости вращения, а не по проскальзыванию

- **Статус:** Принят
- **Дата:** 2026-10-11
- **Затронуто:** `GameParsers/Parser.cs` (`GetInRaceLeftTriggerInstruction`, `GetBrakeLock`),
  `GameParsers/ForzaParser.cs`, `GameParsers/DirtParser.cs`, `DataPacket.cs`

## Контекст

Пользователь: на гравии при торможении с полной блокировкой колёс тормозной триггер не даёт
никакой отдачи, на асфальте всё в порядке.

Оригинальная логика считала потерей сцепления среднее «комбинированное проскальзывание»
больше `GripLossValue` (0.05) при тормозе больше 100 из 255. В этом режиме частота вибрации
бралась из проскальзывания на шкале 0.05…5 → 0…`MaxVibration`. Если частота выходила не больше
`MinVibration`, сопротивление триггера **обнулялось**. При настройках 15/20 вибрация включалась
только при проскальзывании выше ~4.0.

Реальные записи FH6 (`recordings/`, раллийные шины) показали:

| | Гравий | Асфальт |
|---|---|---|
| Проскальзывание полностью заблокированного колеса | упирается в ~3.15 | упирается в ~5.6 |
| Триггер при торможении (стоковая логика, прогон записи через exe) | **0 в 100% времени** | вибрация 61%, ноль 39% |

Forza нормирует проскальзывание на сцепление покрытия, поэтому одна и та же полная блокировка
даёт разные числа на разных покрытиях. На гравии порог недостижим. Вдобавок на сыпучем
покрытии проскальзывание почти всегда больше 0.05, так что даже обычное торможение уходило в
ветку «потеря сцепления» с нулевым сопротивлением.

## Решение

Блокировка определяется напрямую: **колесо крутится медленнее, чем едет машина.**

- Для каждого колеса считается «коэффициент качения» = скорость поверхности шины / скорость
  машины. При качении он около 1, у заблокированного колеса около 0, на любом покрытии.
  В записях распределение двугорбое: 0.8–1.0 или меньше 0.1, промежуточных значений мало.
- Forza присылает вращение колеса в рад/с. Радиус колеса `ForzaParser` подстраивает на ходу:
  в моменты свободного качения (тормоз 0, газ ≤ 60/255, скорость > 8 м/с, колесо на земле,
  |slip ratio| < 0.1) значение плавно сдвигается к `скорость / вращение`. Начальное значение
  0.32 м измерено по записям. CarOrdinal в FH6 приходит нулём, поэтому определить машину и
  взять радиус из таблицы нельзя.
- Dirt присылает скорость колеса сразу в м/с, радиус там не нужен.
- Степень блокировки колеса: 0 при коэффициенте ≥ 0.6, 1 при ≤ 0.1, линейно между ними.
  Колёса в воздухе (нормированный ход подвески ≤ 0.02) пропускаются: заторможенное колесо
  останавливается, как только отрывается от земли, а на гравии это бывает (в записи есть кадры,
  где все четыре колеса в воздухе).
- **Вибрация** включается, когда хотя бы одно колесо заблокировано на ≥ 0.5 при тормозе > 20
  и скорости > 3 м/с. Частота: от `MinVibration` до `MaxVibration` по средней блокировке
  четырёх колёс (одно колесо → около Min, все четыре → Max). Жёсткость считается, как раньше,
  от `Min/MaxStiffness` по силе нажатия.
- **Без блокировки** триггер всегда даёт обычное сопротивление по силе нажатия. Проскальзывание
  без блокировки больше не обнуляет его.
- У жёсткости вибрации теперь своё состояние фильтра (`lastBrakeStiffness`). Раньше она делила
  его с обычным сопротивлением, хотя у них разные шкалы. Каждая новая блокировка начинается
  сразу с полной силы, без разгона фильтра.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Снизить порог проскальзывания для гравия | Порог зависит от покрытия и шин; один на все случаи не подобрать, а покрытие в телеметрии не передаётся. |
| `TireSlipRatio` вместо комбинированного проскальзывания | Тоже нормирован на сцепление покрытия: −3.15 на гравии, −5.6 на асфальте. Та же проблема. |
| Фиксированный радиус 0.32 м без подстройки | На машинах с крупными колёсами (внедорожники, грузовики) свободное качение выглядело бы как частичная блокировка. |
| «Провал» сопротивления при блокировке вместо вибрации | Пользователь выбрал вибрацию: её трудно не заметить, и на асфальте она уже была привычна. |

## Последствия

- Прогон реальных записей через exe (`tools/check_brake_replay.ps1`), доля времени торможения:

  | | До | После |
  |---|---|---|
  | Гравий, все торможения | ноль 100% | вибрация 80%, сопротивление 17%, ноль 3% |
  | Гравий, торможения с блокировкой ≥ 50% | ноль 100% | вибрация 85%, сопротивление 15% |
  | Асфальт, все торможения | вибрация 61%, ноль 39% | вибрация 72%, сопротивление 28% |

  Доля вибрации в каждом торможении почти совпадает с долей времени, когда колёса были
  заблокированы (например, 93% → 95%, 54% → 55%). Торможение без блокировки вибрации не даёт.
  Оставшийся «ноль» — это начало нажатия, где кривая сопротивления (`MinResistance` = 0) ещё
  на нуле. Так было и раньше.
- Смысл настроек тормоза изменился:
  - `MinVibration` / `MaxVibration` — частота при блокировке одного колеса / всех четырёх;
  - **`GripLossValue` на вкладке Brake больше ни на что не влияет;**
  - жёсткое условие «тормоз > 100» заменено на «тормоз > 20».
- Вибрация при блокировке теперь зависит только от колёс, поэтому при включённом в игре ABS
  (колёса не блокируются) её почти не будет. Это ожидаемо.
- Синтетическим тестам нужны правдоподобные скорости колёс: `tools/fake_forza.ps1` теперь
  крутит колёса со скоростью машины и умеет блокировать N колёс (`-LockWheels`). Без этого
  все колёса выглядели бы заблокированными.
- Логика для Dirt изменена так же, но реальной записью не проверена.

## Обновление 2026-10-11

Порог «тормоз > 20» теперь берётся из настройки тормоза Vibration Mode Start (по умолчанию 30),
а Grip Loss на вкладке тормоза отключён. Подробности и найденная ошибка с жёсткостью — в ADR-0010.
