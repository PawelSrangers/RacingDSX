# 0012. Разработка от спецификаций

- Status: Accepted
- Date: 2026-10-19

## Relations

- Depends-on: none
- Supersedes: none
- Constrains: none
- Related: 0007, 0011

## Context

Код пишут ИИ-агенты. Без зафиксированного источника истины агент толкует требования на ходу,
расширяет объём работы и молча подгоняет требования под то, что реализовал. В этом проекте
нужное поведение до сих пор жило в описаниях ADR, в результатах `tools/` и в разговорах.
Например, «вибрация на тормозе следует за долей блокировки в пределах нескольких пунктов» —
это требование, но записано оно только как наблюдение в ADR-0009 и AGENTS.md.

## Considered options

1. Спецификации в `specs/` — источник истины. Меняются только отдельными spec-PR с
   одобрением человека; PR с кодом ссылаются на ID требований.
2. Разрешить менять спецификацию в одном PR с кодом. Церемоний меньше, но ревьюер не видит,
   намеренно ли изменилось поведение, а агент может переписать спецификацию под свой код.
3. Без спецификаций, требования в задачах и чатах. Трассируемости нет.

## Decision

Вариант 1. Spec-PR и PR с реализацией разделены. У каждого требования стабильный ID
`REQ-<FEATURE>-NNN`; PR с реализацией и тесты ссылаются на эти ID.

Применение к этому проекту:

- первые спецификации (2026-10-19) описывают уже работающее поведение, восстановленное из
  кода, ADR-0001…0010 и измерений `tools/`. Они начинают со статуса `Draft`, и владелец
  переводит их дальше сам;
- тесты здесь — black-box-скрипты из `tools/` (ADR-0007). Трассируемость обеспечивается
  ссылкой на REQ ID в шапке скрипта и в разделе Testing PR, а не в имени unit-теста;
- у репозитория пока нет remote. До его появления то же разделение действует для коммитов:
  коммит меняет либо `specs/`, либо код.

## Consequences

- Изменение поведения стоит лишнего PR и раунда одобрения.
- Агент обязан остановиться и сообщить, если спецификация неверна или неоднозначна, а не
  угадывать.
- Проект с одним мейнтейнером: GitHub не даёт одобрить собственный PR, поэтому одобрение —
  это merge владельца. Агентам запрещён `gh pr merge` (`.claude/settings.json`).
- Правила в AGENTS.md — не принуждение. Пока нет remote, branch protection, CI и CODEOWNERS,
  разделение держится только на дисциплине агентов и ревью.
- Затронуто: `specs/`, `.github/`, `AGENTS.md`, `.claude/settings.json`.
