# ADR-0007: Тестирование чёрным ящиком через UDP, без unit-тестов

- **Статус:** Принят
- **Дата:** 2026-09-09
- **Затронуто:** `tools/fake_forza.ps1`, `tools/fake_dsx.ps1`, `tools/run_harness.ps1`,
  `tools/screenshot_ui.ps1`

## Контекст

В проекте нет тестов. Главный баг (ADR-0001) — это свойство **потока сообщений между
процессами**: сколько пакетов в секунду уходит в DSX при заданной частоте телеметрии. На уровне
одной функции он не виден.

Чтобы покрыть воркер unit-тестами, пришлось бы:

- убрать статические сокеты (`client`, `senderClient`) и внедрять их извне;
- отвязать воркер от `IProgress` UI и от глобального `FMData.BufferOffset`;
- подменить время (`Stopwatch`) для проверки лимита частоты.

Это заметный рефакторинг апстрим-кода, который мы стараемся не перекраивать (см. ADR-0006
про расхождение с апстримом).

Проверять на настоящей игре тоже нельзя: FH6 и DSX нельзя запустить автоматически, и
результат не воспроизводится.

## Решение

Тестируется **собранный exe** как чёрный ящик, обе стороны подменяются по UDP:

- `fake_forza.ps1` шлёт 324-байтные пакеты Horizon с заданной частотой (140 Гц — условия FH6,
  60 Гц — FH5) на порт 5300. Ключ `-Idle` даёт стоящую машину.
- `fake_dsx.ps1` слушает порт 6969, записывает каждый пакет с меткой времени и считает
  частоту в установившемся режиме.
- `run_harness.ps1` разворачивает exe в `%TEMP%` с `DisableAppCheck: true`, запускает всё
  вместе и печатает результат. `-StopEarly` проверяет ADR-0002, `-ExePath` позволяет сравнить
  с оригиналом из `backup_original/`.
- `screenshot_ui.ps1` снимает окно запущенного приложения, при необходимости кликнув по
  вкладке. Это единственный способ проверить правки UI без дизайнера (ADR-0005).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| xUnit-проект с рефакторингом воркера | Большой рефакторинг ради тестов. Статические сокеты и связь с UI пришлось бы переделывать. |
| Проверять только на реальной игре | Невоспроизводимо и не автоматизируется. Нельзя сравнить с исходной версией. |
| Сниффер трафика (Wireshark) | Loopback на Windows ловится плохо, нужна установка, результат не скриптуется. |

## Последствия

- Проверяется ровно то, что получит пользователь, включая сериализацию JSON и сокеты.
- A/B со стоковой версией даёт конкретные числа: **419 против 28 пакетов/с**.
- Для запуска нужен свободный порт 6969. Если работает настоящий DSX, harness откажется
  стартовать, а не отберёт порт.
- Логику отдельных фильтров (`Map`, EWMA) harness проверяет только косвенно. Если появится
  сложная логика триггеров, стоит пересмотреть это решение и добавить unit-тесты на парсер,
  который зависит от сокетов меньше, чем воркер.
- Совпадение симуляции с реальной FH6 + DSX подтверждено документацией (размер пакета,
  частота), но не прогоном на настоящей игре.
