# ADR-0003: FH6 идёт по общему пути FH4/FH5, без отдельного парсера

- **Статус:** Принят
- **Дата:** 2026-09-09
- **Затронуто:** `RacingDSXWorker.AdjustToBufferType`, `Config/ConfigHandler.cs`

## Контекст

Тип игры определяется только по длине UDP-датаграммы (`AdjustToBufferType`). Эта же функция
выставляет глобальный `FMData.BufferOffset`. Первым подозрением было, что FH6 сменил формат
пакета и парсер читает мусор.

Проверка по официальной документации FH6 Data Out и сторонним реализациям показала другое:

- пакет FH6 — **324 байта**, как у FH4/FH5;
- раскладка **байт-в-байт совпадает** с FH5;
- 12 байт между `NumCylinders` и `PositionX`, которые `BufferOffset = 12` пропускает, —
  это поля `CarGroup`, `SmashableVelDiff`, `SmashableMass`. Microsoft впервые
  задокументировала их для FH6.

## Решение

- Отдельного `GameType` или парсера для FH6 нет. Ветка `case 324` обслуживает FH4, FH5 и FH6,
  о чём в коде есть комментарий.
- `ForzaHorizon6` добавлен в исполняемые файлы профиля Forza по умолчанию
  (`ConfigHandler.AddDefaultProfiles`), чтобы его видел AppCheck.
- Пакет неизвестной длины по-прежнему отбрасывается, но теперь об этом **один раз** на каждую
  новую длину пишется сообщение в лог UI. Раньше отбрасывание было молчаливым.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Отдельный `GameType.ForzaHorizon6` и парсер | Дублирование без единого отличия в данных. Длина пакета та же, так что различить FH5 и FH6 по пакету всё равно нельзя. |
| Определять игру по имени процесса из AppCheck | Связывает парсинг с UI-потоком и не даёт ничего: формат одинаковый. |

## Последствия

- Отличия FH6 касаются не формата, а **поведения потока**: частоты и пауз. Они решены в
  ADR-0001 и ADR-0002, а не в парсере.
- Если патч игры изменит размер пакета, в логе появится «Ignoring telemetry packet of
  unsupported size N bytes» вместо молча неработающей программы. По N будет понятно, что
  добавлять в `AdjustToBufferType`.
- `FMData.BufferOffset` остаётся изменяемым глобальным static. Пока работает один воркер, это
  безопасно. Если когда-нибудь появятся два параллельных парсера, оно сломается первым.
