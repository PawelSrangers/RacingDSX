# ADR-0010: Настройки вкладки Brake Trigger соответствуют коду

- **Статус:** Принят. Дополняет ADR-0009.
- **Дата:** 2026-10-11
- **Затронуто:** `UI.cs`, `UI.Designer.cs` (тексты подписей), `GameParsers/Parser.cs`

## Контекст

После ADR-0009 пользователь спросил, не противоречат ли настройки коду. Сверка всех настроек
тормоза и газа с тем, что читает `Parser`, и всех обработчиков ползунков в `UI.cs` показала
следующее. Вкладка газа согласована полностью. На вкладке тормоза четыре расхождения:

1. **Ошибка оригинала в Min/Max Stiffness.** Обработчики числовых полей жёсткости читали
   значение из поля *вибрации* и двигали ползунок вибрации. `SwitchDisplayedProfile` при каждом
   запуске выставляет эти поля, поэтому `MinStiffness := MinVibration` и
   `MaxStiffness := MaxVibration` перезаписывались при старте, а значение, выставленное
   ползунком жёсткости, жило только до перезапуска.
   Следы в конфиге пользователя: у Forza жёсткость 15/20 ровно как вибрация 15/20, причём уже в
   `backup_original` (до наших правок). Профиль Dirt в UI не открывался и сохранил значения
   по умолчанию 150/5.
   Проверка `probe_brake.ps1` с конфигом 150/5: старый exe отправлял на блокировке силу 15,
   исправленный — 135–148.
2. **Названия Min/Max Stiffness перевёрнуты.** Код берёт `MaxStiffness` при лёгком нажатии и
   `MinStiffness` при полном (`Map(Brake, 0, 255, MaxStiffness, MinStiffness)`), так что при
   значениях по умолчанию «Min» = 150 больше «Max» = 5.
3. **Vibration Mode Start тормоза не использовался вообще**, даже в оригинале.
4. **Grip Loss Value тормоза** ни на что не влияет после ADR-0009.

## Решение

1. Обработчики жёсткости читают и обновляют свои собственные контролы.
2. Подписи поменяны на «Stiffness at Full Brake» (`MinStiffness`) и «Stiffness at Light Brake»
   (`MaxStiffness`). Ключи конфига и порядок отображения сохранены: старые конфиги читаются
   как прежде.
3. Тормозной **Vibration Mode Start** — минимальное нажатие тормоза (0–255), с которого
   блокировка даёт вибрацию. Он заменил зашитую константу 20. Значение по умолчанию и
   у пользователя — 30 (~12% хода). Смысл совпадает с одноимённой настройкой газа.
4. Поле **Grip Loss** на вкладке тормоза отключено, подпись «Grip Loss (not used)». Значение в
   конфиге остаётся, чтобы не ломать старые файлы и иметь возможность вернуть его.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Переименовать ключи конфига (`MinStiffness` → `FullBrakeStiffness`) | Старые конфиги потеряли бы значения при чтении; хватает понятных подписей. |
| Использовать Grip Loss как чувствительность блокировки | Натянутое значение для поля с таким названием; порог блокировки по скорости колёс от покрытия не зависит, и настраивать его пока не нужно. |
| Убрать Grip Loss с вкладки | Нужна правка разметки в дизайнерском файле без Visual Studio. Отключённое поле с подписью честнее и проще. |

## Последствия

- Значения жёсткости в конфиге наконец-то действуют и переживают перезапуск.
- **Сохранённые у пользователя 15/20 он сам не выбирал — их записала ошибка.** Сила вибрации
  на блокировке сейчас 15–20 из 255, а задумано до 150. Менять живой конфиг без согласия
  пользователя нельзя (см. CLAUDE.md), поэтому значения оставлены как есть, а выбор за ним.
- Вибрация при блокировке включается при нажатии больше 30/255, а не больше 20.
