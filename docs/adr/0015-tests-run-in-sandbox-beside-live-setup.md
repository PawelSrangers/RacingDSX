# 0015. Проверки работают в песочнице на своих портах, рядом с настоящими DSX и RacingDSX

- Status: Accepted
- Date: 2026-10-11

## Relations

- Depends-on: 0007
- Supersedes: none
- Constrains: none
- Related: 0006, 0014

## Context

В первой версии инструментов (ADR-0007, коммит `4cdc5c9`) проверки занимали настоящие порты:

- `run_harness.ps1` отказывался стартовать, если запущен RacingDSX или занят UDP 6969
  («real DSX running?»);
- `probe_brake.ps1` требовал свободные 5300 и 6969, а в конце выполнял
  `Get-Process RacingDSX | Stop-Process -Force`, то есть убивал по имени и RacingDSX
  пользователя, если тот был открыт;
- папки песочниц были фиксированные (`%TEMP%\racingdsx_harness`,
  `%TEMP%\racingdsx_brake_probe`) и удалялись перед каждым запуском.

Exe пользователя, DSX и игра работают на той же машине, где агент гоняет проверки. Закрыть
DSX значит лишиться виртуального пада, через который игра читает стики. Проверка, которая
требует закрыть рабочее окружение или молча закрывает его сама, мешает пользователю.

## Considered options

1. **Как было: свободные 5300/6969, закрыть DSX и RacingDSX перед проверкой.** Просто, но
   каждый прогон ломает пользователю игру, а убийство процесса по имени задевает чужой
   процесс.
2. **Отдельные фиксированные порты для песочницы, остановка только своего процесса.**
   Проверки идут рядом с живым окружением. Две проверки одновременно не запустятся: вторая
   увидит занятый порт.
3. **Случайные свободные порты на каждый прогон.** Можно гонять проверки параллельно, но
   порты надо прокидывать во все вспомогательные скрипты, а «занято — значит, идёт другая
   проверка» уже не проверить так просто.
4. **Отдельная машина или виртуалка для тестов.** Её нет.

## Decision

Вариант 2 (коммит `1028cf8`):

- Проверки (`run_harness.ps1`, `probe_brake.ps1`, `check_brake_replay.ps1`) копируют exe и
  `RacingDSX.dll.config` в новую папку `%TEMP%\racingdsx_*_<HHmmss>` и запускают копию оттуда.
- Конфиг песочницы делается из живого `RacingDSX_exe/RacingDSX.json` заменой трёх значений:
  `DisableAppCheck: true`, `gameUDPPort: 5310`, `DSXPort: 6970`. Живой конфиг только
  читается.
- Фейковая игра и фейковый DSX работают на 5310 и 6970. Если эти порты заняты, проверка
  падает с сообщением, а не пытается их занять.
- Останавливается только запущенная копия: `Stop-Process -Id $app.Id`. Процессы RacingDSX и
  DSX по имени не трогаются никогда.

## Consequences

- Проверки можно запускать при открытых DSX, RacingDSX пользователя и игре.
- Пункт последствий ADR-0007 «нужен свободный порт 6969; если работает настоящий DSX, harness
  откажется стартовать» больше не верен. Само решение ADR-0007 (чёрный ящик по UDP) не
  меняется, поэтому оно не заменяется, а уточняется этим ADR.
- **Правило:** новая проверка не использует 5300 и 6969 и не останавливает процессы по имени.
- Вспомогательные скрипты (`fake_forza.ps1`, `fake_dsx.ps1`, `replay_recording.ps1`) при
  запуске напрямую по умолчанию по-прежнему смотрят на 5300 и 6969; обёртки передают им
  `-Port`. Запуская их вручную, порт нужно указывать самому.
- Параллельно две проверки не идут: порты общие для всех песочниц.
- Песочницы в `%TEMP%` больше не удаляются автоматически и копятся.
- Запись телеметрии (ADR-0014) — исключение: игра шлёт только на 5300, поэтому RacingDSX
  пользователя на время записи закрывает он сам.
- Затронуто: `tools/run_harness.ps1`, `tools/probe_brake.ps1`, `tools/check_brake_replay.ps1`.
