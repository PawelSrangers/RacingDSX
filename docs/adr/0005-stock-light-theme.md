# ADR-0005: Стандартная светлая тема вместо самодельной тёмной

- **Статус:** Принят
- **Дата:** 2026-09-09
- **Затронуто:** `UI.Designer.cs` (оригинал сохранён в `UI.Designer.cs.darktheme.bak`)

## Relations

- Depends-on: 0013
- Supersedes: none
- Constrains: none
- Related: 0001, 0007, 0010

## Контекст

Апстрим вручную покрасил интерфейс в тёмный цвет: `BackColor = FromArgb(18,18,18)` и
`ForeColor = White` прописаны примерно на 150 контролах. Покраска неполная:

- форма и панели тёмные, а полоса вкладок `TabControl` и `StatusStrip` остались светлыми,
  потому что без owner-draw они не учитывают `BackColor`;
- у `profilesGroupBox` не задан `ForeColor`, поэтому заголовок «Profiles» получился чёрным по
  чёрному и был не виден;
- 9 кнопок с `UseVisualStyleBackColor = false` выглядели чужеродно.

Пользователь назвал это проблемой («фон чёрный»). Visual Studio здесь не установлена, поэтому
дизайнер открыть нельзя, и правки возможны только текстом.

## Решение

По выбору пользователя тема возвращена к стандартной светлой Windows:

- удалены все 159 строк покраски. Значений было ровно три (`FromArgb(18,18,18)`,
  `FromArgb(12,12,12)`, `Color.White`), и все — простые присваивания, поэтому чистка сделана
  скриптом-фильтром по строкам с проверкой формы каждой удаляемой строки;
- 9 кнопок получили `UseVisualStyleBackColor = true`;
- результат проверен скриншотами собранного приложения на всех вкладках.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Довести тёмную тему до конца | Нужны owner-draw для `TabControl`, свой `ToolStripRenderer` для статус-бара и ручная правка дизайнерского файла без дизайнера. Много кода ради внешнего вида; пользователь выбрал светлую. |
| Тёмная тема через системный dark mode | В .NET 8 WinForms его нет (`Application.SetColorMode` появился в .NET 9). Переход на .NET 9 ради темы — отдельное решение со своими рисками. |

## Последствия

- Интерфейс однородный и читаемый, все системные контролы выглядят как в Windows.
- Тёмную версию можно вернуть из `UI.Designer.cs.darktheme.bak`, но с теми же дефектами.
- **Правило:** не возвращать покраску отдельных контролов. Если понадобится тёмная тема,
  её нужно делать на уровне формы, включая `TabControl` и `StatusStrip`, и оформлять новым ADR,
  заменяющим этот.
- Способ «скриптовый фильтр по дизайнерскому файлу плюс проверка скриншотом»
  (`tools/screenshot_ui.ps1`) — рабочий подход для массовых правок UI без Visual Studio.
