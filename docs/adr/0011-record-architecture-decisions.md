# 0011. Записывать архитектурные решения с машиночитаемыми связями

- Status: Accepted
- Date: 2026-10-19

## Relations

- Depends-on: none
- Supersedes: none
- Constrains: none
- Related: 0001, 0002, 0003, 0004, 0005, 0006, 0007, 0008, 0009, 0010, 0012

## Context

ADR-0001…0010 писались в свободном формате Найгарда: связи между решениями были только в
тексте («Дополняет ADR-0001», «решено в ADR-0009»). Код почти целиком пишут ИИ-агенты, и им
нужен структурированный способ понять, какие решения ломаются при изменении более раннего.
Пример из истории проекта: ADR-0001 (лимит частоты) молча сломал доставку коротких блокировок,
и это обнаружилось только через месяц (ADR-0008). Явный граф зависимостей сделал бы такую
связь видимой при любом пересмотре ADR-0001.

Проект перешёл на шаблон `scaffold-agentic-project`. В шаблоне это ADR-0001, но здесь номера
0001–0010 уже заняты, а номера ADR не переиспользуются.

## Considered options

1. ADR с явным разделом `Relations` (`Depends-on` / `Supersedes` / `Constrains` / `Related`):
   лёгкий формат, из которого строится граф.
2. ADR плюс отдельные деревья решений: больше артефактов, они дублируют раздел
   «Considered options» и расходятся с ним.
3. Без формальных записей, знание живёт в чатах и в головах. Для проекта, где контекст между
   сессиями агентов теряется, это не вариант.

## Decision

Вариант 1. Деревья решений допускаются только как встроенная Mermaid-диаграмма внутри ADR,
когда ветвление действительно многоуровневое.

Переход для существующих ADR:

- в ADR-0001…0010 добавлен раздел `## Relations` со связями, восстановленными из их текста и
  истории git. Само решение, контекст и последствия в них не менялись. Это единственная
  разрешённая правка старых ADR кроме строки статуса, и она разовая;
- новые ADR копируют `docs/adr/0000-template.md`: заголовки разделов и ключи `Relations` на
  английском (машиночитаемые), текст на русском, как в остальных ADR;
- каждый новый ADR добавляется в индекс `docs/adr/README.md`.

## Consequences

- Каждое значимое решение стоит короткого markdown-файла.
- Агент перед изменением строит граф из `Relations` и перечисляет затронутые ADR
  (см. AGENTS.md, раздел «Architecture Decision Records»).
- У старых ADR формат смешанный: русские заголовки и английский раздел `Relations`. Приводить
  их к шаблону целиком нельзя: принятые ADR неизменяемы.
- Затронуто: `docs/adr/`, `AGENTS.md`.
