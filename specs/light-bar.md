# Spec: Light bar

- Status: Draft
- Feature ID: LIGHTBAR
- Owner: abramovdima1998 (владелец репозитория)
- Related ADRs: 0001, 0002, 0003, 0004
- Related specs: specs/dsx-output.md, specs/telemetry-input.md, specs/settings-ui.md

## Problem

Лайтбар DualSense — единственный визуальный канал RacingDSX. Во время езды он работает как
индикатор оборотов: от зелёного через жёлтый к красному и сплошной красный у отсечки. Вне
гонки апстрим окрашивал его в цвет класса машины Forza. Логика унаследована от апстрима
0.6.7; форк исправил только деление на ноль, когда обороты ещё не пришли (ADR-0004).

Спецификация фиксирует текущее поведение, чтобы изменения цвета делались осознанно.

## Goals

- Во время езды цвет лайтбара показывает обороты двигателя относительно диапазона машины.
- У отсечки (настраиваемая доля оборотов) лайтбар сплошной красный.
- Отсутствие данных об оборотах не ломает цвет и поток команд.

## Non-goals / Out of scope

- Настройка цветов, яркости или включение/выключение лайтбара: таких настроек нет.
- Светодиоды игрока, микрофона и прочие индикаторы DualSense: RacingDSX их не трогает
  (REQ-OUTPUT-002).
- Мигание, анимации, индикация переключения передач.
- Когда и как команда лайтбара уходит в DSX (в одной датаграмме с триггерами, с
  ограничением частоты) — `specs/dsx-output.md`.
- Как определяется состояние «в гонке / вне гонки» — `specs/telemetry-input.md`.
- Цвет лайтбара при остановке телеметрии: сообщение отпускания триггеров лайтбар не меняет
  (REQ-OUTPUT-007), лайтбар остаётся с последним цветом.

## Requirements

Формат команды (UDP API DSX, `type` 2): в гонке `[0, R, G, B, 255]`, вне гонки
`[0, R, G, B]`.

Обозначения: `rpm`, `idle`, `max` — текущие, холостые и максимальные обороты из телеметрии;
доля оборотов `k` = clamp((`rpm` − `idle`) / (`max` − `idle`), 0, 1), а если
`max` − `idle` ≤ 0, то `k` = 0.

### REQ-LIGHTBAR-001: Цвет по оборотам во время езды

- Status: Active
- Description: В гонке система MUST отправлять лайтбару цвет `R` = floor(255 × `k`),
  `G` = max(floor(255 × (1 − `k`)), 50), `B` = 0 и яркость 255. Зелёный канал MUST NOT
  опускаться ниже 50 до отсечки.
- Acceptance criteria:
  - Given `idle` = 800, `max` = 8000, `rpm` = 4400 (`k` = 0.5), `RPMRedlineRatio` = 0.9, then
    команда лайтбара `[0, 127, 127, 0, 255]`.
  - Given `rpm` = 6920 (`k` = 0.85), then `[0, 216, 50, 0, 255]`.
  - Given `rpm` = 800, then `[0, 0, 255, 0, 255]`.
  - Проверка: нет автоматической проверки. Значения видны в `capture.json` прогона
    `tools/run_harness.ps1` (fake_forza даёт `idle` 800, `max` 8000, `rpm` 4000 ± 3000), но
    скрипт их не сравнивает.

### REQ-LIGHTBAR-002: Отсечка

- Status: Active
- Description: Когда `k` ≥ `RPMRedlineRatio` активного профиля, система MUST отправлять
  `[0, 255, 0, 0, 255]` (сплошной красный).
- Acceptance criteria:
  - Given `RPMRedlineRatio` = 0.9, `idle` = 800, `max` = 8000, when `rpm` = 7280 (`k` = 0.9),
    then `[0, 255, 0, 0, 255]`; when `rpm` = 7279, then не сплошной красный.
  - Given `RPMRedlineRatio` = 1.0, `rpm` = `max`, then `[0, 255, 0, 0, 255]`.
  - Проверка: нет автоматической проверки.

### REQ-LIGHTBAR-003: Нет данных об оборотах

- Status: Active
- Description: Если `max` − `idle` ≤ 0 (машина ещё не загружена, оба поля 0, или игра их не
  присылает), система MUST считать `k` = 0 и отправлять корректный цвет без NaN и без
  остановки потока команд.
- Acceptance criteria:
  - Given в гонке `idle` = `max` = 0, `RPMRedlineRatio` = 0.9, then `[0, 0, 255, 0, 255]`.
  - Проверка: нет автоматической проверки.

### REQ-LIGHTBAR-004: Цвет класса машины вне гонки (Forza)

- Status: Active
- Description: Вне гонки в профиле Forza система MUST отправлять цвет класса машины,
  умноженный на min(`p`, 255) / 255 с округлением вниз, где `p` — индекс производительности
  машины (PI, целое 100–999 из пакета, читается полностью). Поскольку PI почти всех машин
  ≥ 255, на практике это полный цвет класса. Палитра: D (0) — (107, 185, 236), C (1) —
  (234, 202, 49), B (2) — (211, 90, 37), A (3) — (187, 59, 34), S1 (4) — (128, 54, 243),
  S2 (5) — (75, 88, 229); класс выше 5 — (105, 182, 72) без умножения. Класс и индекс MUST
  браться из последнего кадра телеметрии (в гонке или вне её), где они были ненулевыми:
  FH6 присылает вне гонки нулевые кадры, и без этого лайтбар гас бы. До первого такого кадра
  класс D и `p` = 0, то есть `[0, 0, 0, 0]`.
- Acceptance criteria:
  - Given стоящая машина (fake_forza `-Idle`: класс 4, `p` = 200, обороты не меняются) и
    наступило состояние «вне гонки», then команда лайтбара `[0, 100, 42, 190]`.
  - Given класс 4 и `p` = 557 (как в записях FH6), then `[0, 128, 54, 243]`.
  - Given в гонке приходили кадры с классом 4 и `p` = 557, затем кадры вне гонки с нулевыми
    классом и индексом, then `[0, 128, 54, 243]`, а не `[0, 0, 0, 0]`.
  - Given ни одного кадра с ненулевыми классом и индексом, then `[0, 0, 0, 0]`.
  - Проверка: нет автоматической проверки. Вручную: `tools/replay_recording.ps1` с записью из
    `recordings/` (порт 5310) и `tools/fake_dsx.ps1 -Port 6970` в песочнице.

### REQ-LIGHTBAR-005: Порог отсечки настраивается в профиле

- Status: Active
- Description: Порог отсечки MUST задаваться полем профиля `RPMRedlineRatio` в
  `RacingDSX.json` (доля 0.00–1.00, по умолчанию 0.9) и настройкой «RPM Redline Ratio» на
  вкладке Misc (0–100, то есть сотые доли). Изменение порога у активного профиля MUST
  действовать без перезапуска программы (поведение UI — `specs/settings-ui.md`).
- Acceptance criteria:
  - Given `RPMRedlineRatio` = 0.5 в конфиге, `k` = 0.5, then `[0, 255, 0, 0, 255]`.
  - Проверка: нет автоматической проверки.

## Constraints

Значения из кода (`GameParsers/Parser.cs`, `GameParsers/ForzaParser.cs`, `Config/Profile.cs`)
на 2026-10-19.

- Цвет вычисляется на каждом кадре телеметрии в гонке; отправляется вместе с триггерами в
  одной датаграмме с ограничением частоты (`specs/dsx-output.md`).
- Минимум зелёного канала до отсечки — 50; яркость в гонке — константа 255.
- Профили Dirt и (None) всегда считаются «в гонке» (их телеметрия не сообщает обратного),
  поэтому для них действует только REQ-LIGHTBAR-001…003. У Dirt `idle` всегда 0. Цвет вне
  гонки по умолчанию для таких профилей (220, 120, 220) в коде есть, но недостижим.
- Значение по умолчанию: `RPMRedlineRatio` = 0.9.

## Open questions

- **OQ-1 (решён 2026-10-19):** PI читался одним байтом, и программа видела `PI mod 256`
  (557 → 45, яркость ~18%). Владелец: «поправим lightbar». PI читается полностью
  (REQ-LIGHTBAR-004). Шкала яркости `min(p, 255) / 255` из апстрима сохранена, поэтому
  яркость больше не зависит от PI почти ни у одной машины. Если нужна яркость по PI внутри
  класса, это новое требование.
- **OQ-2 (решён 2026-10-19):** на FH6 кадры вне гонки нулевые (в записях 644 и 917 кадров),
  поэтому лайтбар гас в `[0, 0, 0, 0]`. Решено вместе с OQ-1: класс и индекс запоминаются из
  любого кадра, включая кадры гонки (REQ-LIGHTBAR-004). В меню и на паузе FH6 телеметрию не
  шлёт вовсе; там лайтбар по-прежнему держит последний цвет (OQ-4).
- **OQ-3 (non-blocking):** команда вне гонки — 4 параметра без яркости
  (`ForzaParser.cs:133`), в гонке — 5 (`Parser.cs:100`). Как DSX трактует отсутствие яркости,
  не проверялось.
- **OQ-4 (non-blocking):** при остановке телеметрии лайтбар остаётся с последним цветом
  (ADR-0002, п. 4). На FH6 это значит, что в меню лайтбар может гореть красным (если игра
  поставлена на паузу на отсечке) до следующей езды. ADR-0002 считает это приемлемым;
  подтвердить.
